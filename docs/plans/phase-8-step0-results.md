# Phase 8: Step 0 research results (input to gate G2)

Date: 2026-11-10. Companion to [phase-8-first-deployment.md](phase-8-first-deployment.md) (WP1, questions Q1-Q8).
Method: official pages fetched by haiku agents (`web-fetch`, one URL list per question group). A first attempt with `ecc:docs-lookup` agents returned nothing, because those agents had no fetch tool in this session; they reported "NOT FOUND" and answered nothing from memory, so it was discarded. The findings below were **reported by the agents and not re-fetched by the main session**; the ones that change a design decision are marked and should be spot-checked at G2. Nothing here touched AWS and no credential was used.

Legend: **confirmed** = stated on an official page (URL given); **not stated** = the page was read and does not say it, so the plan's assumption (A) or unverified item (U) stays open.

## Results

| # | Finding | Status | Effect on the plan |
|---|---|---|---|
| Q1 | `aws configure export-credentials` has `--format`, default `process`; values `process`, `env`, `env-no-export`, `powershell`, `windows-cmd`, `fish`. `process` is "JSON output, in the schema expected by the `credential_process` config value". ([export-credentials](https://docs.aws.amazon.com/cli/latest/reference/configure/export-credentials.html)) | confirmed | T2's "flag and format (A)" is now confirmed for the flag and the `process` JSON format. | Q1 | The JSON field names (and so the expiry field and its format), whether SSO credentials always carry a session token, the `ASIA` access-key prefix, and how an issued Identity Center role session is revoked. | **not stated** on that page | T2 requires a session token, an `ASIA` key id and an expiry of at least 60 minutes. Revocation stays open; O5 and §7.3 already assume issued credentials live until they expire. |
| Q2 | The HTTP API logging page lists three steps (permissions, a log group, the log group ARN on the stage) and says nothing about an account-level "CloudWatch Logs role ARN". Its permission list includes `logs:PutResourcePolicy` and `logs:CreateLogDelivery`. ([http-api-logging](https://docs.aws.amazon.com/apigateway/latest/developerguide/http-api-logging.html)) | **not stated** | U11 stays open. | Q3 | SQS: "You must wait 60 seconds after deleting a queue before you can create another queue with the same name"; error `QueueDeletedRecently` (HTTP 400). ([CreateQueue](https://docs.aws.amazon.com/AWSSimpleQueueService/latest/APIReference/API_CreateQueue.html), [DeleteQueue](https://docs.aws.amazon.com/AWSSimpleQueueService/latest/APIReference/API_DeleteQueue.html)) | confirmed | U24 resolved. T12's 90-second wait (60 plus margin) holds. |
| Q3 | CloudFront: a path with `*` counts as one path; `/*` invalidates everything; **1,000 free invalidation paths per month per account**. ([PayingForInvalidation](https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/PayingForInvalidation.html), [specifying objects](https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/invalidation-specifying-objects.md)) | confirmed | T8's single `/*` per publish is well inside the allowance (each publish costs one path). |
| Q3 | CloudFront create and delete durations, and whether invalidating `/index.html` also covers `/` under a default root object. The `/*` choice (decision 11) already makes U12 harmless. P12 and the 60-minute session rule stay as the safeguard for slow CloudFront operations. |
| Q4 | `lambda get-account-settings` returns `AccountLimit` (`CodeSizeUnzipped`, `UnreservedConcurrentExecutions`, `ConcurrentExecutions`, `CodeSizeZipped`, `TotalCodeSize`) and `AccountUsage` (`FunctionCount`, `TotalCodeSize`). ([get-account-settings](https://docs.aws.amazon.com/cli/latest/reference/lambda/get-account-settings.html)) | confirmed | The A0 probe (`query` on `AccountLimit.ConcurrentExecutions` and `UnreservedConcurrentExecutions`) is well defined. |
| Q4 | "You can reserve up to the Unreserved account concurrency value minus 100"; the default quota is 1,000 per Region; "New AWS accounts have reduced concurrency and memory quotas", with no number given. ([concurrency](https://docs.aws.amazon.com/lambda/latest/dg/configuration-concurrency.html), [limits](https://docs.aws.amazon.com/lambda/latest/dg/gettingstarted-limits.html)) | confirmed; new-account number **not stated** | P8 stands: read the real number at A0. The worker cap of 2 and any reservation must leave 100 unreserved; in a new account the quota may be far below 1,000, so decision 7 cannot be made before A0. |
| Q5 | `describe-table` `ItemCount` is updated "approximately every six hours. Recent changes might not be reflected." ([TableDescription](https://docs.aws.amazon.com/amazondynamodb/latest/APIReference/API_TableDescription.html)) | confirmed | U26 resolved. T12's "approximate ItemCount" wording is right; a freshly written table can show 0. The destroy preview must say so. |
| Q5 | When a table with PITR enabled is deleted, DynamoDB creates a system backup named `{table-name}$DeletedTableBackup`, kept 35 days at no extra cost. ([PointInTimeRecovery_Howitworks](https://docs.aws.amazon.com/amazondynamodb/latest/developerguide/PointInTimeRecovery_Howitworks.html)) Whether that backup can be deleted, and whether turning PITR off first avoids it, is **not stated**. | confirmed; deletion and PITR-off effect **not stated** | The plan's V38 allowance for "the DynamoDB system backup" (decision 15) is right. **Spot-check this row at G2** (the main session did not re-read the page). Whether to turn PITR off before A11 stays an owner decision and a real-account test. |
| Q6 | Docker Hub `amazon/aws-cli`: publisher "Amazon Web Services", shown as Verified Publisher. ECR Public: `public.ecr.aws/aws-cli/aws-cli`. The AWS docs say to pin a specific `<major.minor.patch>` tag "as those tags are immutable". ([user guide](https://docs.aws.amazon.com/cli/latest/userguide/getting-started-docker.html), [Docker Hub](https://hub.docker.com/r/amazon/aws-cli)) | confirmed | Two official sources exist. Pin by tag **and** digest. |
| Q6 | The current version number, the **full** sha256 digest (Docker Hub shows only a truncated one for `latest`) and any provenance or signature. The ECR Public gallery page returned no repository detail. | **not stated** | WP3 and the owner must obtain the digest from a pull (`docker pull`, then `docker inspect`), which needs no AWS credentials, and record tag, digest and source at G2. The WP3 pin test then enforces `@sha256:<64 hex>`. |
| Q6 | `aws s3 cp` guesses the MIME type by default ("By default the mime type of a file is guessed when it is uploaded"); `--no-guess-mime-type` turns it off; `--content-type` "overrides any guessed mime types". The page does not say what the guess is based on. ([s3 cp](https://docs.aws.amazon.com/cli/latest/reference/s3/cp.html)) | confirmed; basis of the guess **not stated** | T8 sets `--content-type` explicitly by extension and checks it with `head-object`; that is the right call, since the guess is undocumented. |
| Q7 | `-backend-config` supports partial backend configuration; changing the backend needs `-migrate-state` or `-reconfigure`. The documented non-interactive answer is `-force-copy`. `-input=false` is described only as "will error if input was required". ([init](https://developer.hashicorp.com/terraform/cli/commands/init), [backend](https://developer.hashicorp.com/terraform/language/backend)) | confirmed; whether the migration question counts as "input" **not stated** | T3 omits `-input=false` at A3 and refuses `-force-copy`; that stays the conservative choice. The exact prompt text is still unknown, so the owner reads it when it appears. WP6's scratch-directory test cannot prove this part. |
| Q7 | Whether migration changes or deletes the local `terraform.tfstate` or leaves a backup: **not stated**. `init` "will never delete your existing configuration or state", and the docs strongly recommend backing up `terraform.tfstate` by hand. | **not stated** | The plan already copies the state to a private backup right after A2 and removes the local file only after V40 and the owner's go-ahead (A-x). No change. |
| Q7 | `use_lockfile`: "`s3:GetObject`, `s3:PutObject`, and `s3:DeleteObject` are required on the lock file" (`<key>.tflock`, same bucket); `encrypt` covers the lock file too; `s3:DeleteObject` is not needed on the state object itself. The Terraform version that added `use_lockfile` is **not stated** on the page. ([s3 backend](https://developer.hashicorp.com/terraform/language/backend/s3)) | confirmed; version **not stated** | Follow-up (offline, WP6): check that the bootstrap bucket policy and lifecycle rules do not deny `DeleteObject` on `*.tflock`, or the first plan will fail to release its lock. Terraform is already pinned by image digest, so the version question only matters for the documentation. |
| Q8 | `logs test-metric-filter`: `--filter-pattern` (required, up to 1,024 characters) and `--log-event-messages` (required, 1 to 50 messages); output is `matches[]` with `eventNumber`, `eventMessage`, `extractedValues`. The page describes testing only and no write. ([test-metric-filter](https://docs.aws.amazon.com/cli/latest/reference/logs/test-metric-filter.html)) | confirmed; "evaluates only" is implied, not worded | V30 fixtures must be sent in batches of at most 50 messages. Match counts are read from `matches[]`, as the plan expects. |

## What is still open after Step 0

- **Settled offline during WP2/WP6:** the `export-credentials` JSON field names, expiry field and `ASIA` assumption (T2); the lock-file deletion check on the bootstrap bucket policy; obtaining the AWS CLI image digest.
- **Only a real account answers:** U11 (stage logging role), U12 (`/` versus `/index.html`, harmless under `/*`), U20 (CloudFront durations), the new-account Lambda quota (read at A0), the PITR-off and system-backup behaviour, and the migration prompt text.
- **Nothing contradicts the plan.** No answer requires a change before G2; the two items that add work are the lock-file policy check (WP6) and the image digest (WP3).
